# 0006. リトライは runner 起動前に限る

- Status: Accepted
- Date: 2026-08-08

## Context

`Sandbox operation ... was interrupted while the platform was updating the
sandbox runtime` によるジョブ失敗を、通常利用の中で**2回**観測した。
Cloudflare 側でサンドボックスランタイムが更新され、実行中の操作が中断される。
こちらのバグではなく、運用上の常態と見るべき事象。

放置するとジョブが不定期に失敗し、開発基盤として信用できない。

## Decision

一過性のプラットフォームエラーは自動リトライする。ただし
**runner が起動する前に失敗した場合に限る**（最大3回）。

この境界には理由がある。

| 失敗した時点 | 副作用 | リトライ |
|---|---|---|
| sandbox 作成 / clone / job.json 書き込み | **なし** | ✅ 安全 |
| runner 起動後 | **ユーザーのプロンプトが実行済みかもしれない** | ❌ しない |

runner 起動後の再試行は「同じ処理をやり直す」ではなく
「**プロンプトをもう一度実行する**」であり、意味が違う。コミットが二重に生まれたり、
外部への副作用が二重に走る可能性がある。

判別はメッセージパターンで行う。網羅的ではないが、誤って
「壊れているジョブ」をリトライし続けるより、取りこぼして人間に見せるほうが安全。

## Alternatives

**全面リトライ。** 実装は単純だが、プロンプトの二重実行を招く。冪等性の保証が無い以上、選べない。

**リトライしない。** 観測2回という頻度では、基盤として使い物にならない。

**runner 側にチェックポイントを持たせて途中再開する。** 正しい方向ではあるが、
いま必要な複雑さではない。頻度が上がったら再検討する。

## Consequences

- 起動時の一過性障害でジョブが落ちなくなる
- リトライは `attempts` に記録され、ログにも残る。黙って再試行しない
- runner 起動後の一過性障害は**依然としてジョブを失敗させる**。これは意図した挙動で、
  二重実行を避けるための代償
- 判別パターンは観測に基づくため、新しい文言が出たら追加が要る
